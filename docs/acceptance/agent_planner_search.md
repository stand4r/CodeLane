Текущее поведение (факты):

* Поля поиска/фильтра в панели **нет**: в тулбаре только `Свернуть`, `Журналы`, `Снимки`, `+` (`widgets/AgentPlanner.py:38-65`).
* Дерево всегда показывает **все** задания открытого проекта, сгруппированные по роли (`widgets/AgentPlanner.py:127-135`).
* Оверлей умеет только одно сообщение — «Нет запланированных задач», и только когда заданий нет вообще (`widgets/AgentPlanner.py:70`, `:124`). Сообщения «Ничего не найдено» в коде нет (проверено поиском по проекту).
* Перерисовка выполняется по подписи `(root, jobs)` (`widgets/AgentPlanner.py:120`), а также по таймеру каждые 5 с (`widgets/AgentPlanner.py:80-82`). Значит изменение только текста запроса **не** вызовет перерисовку, если подпись не расширить запросом — это ограничение, которое фича обязана снять.
* Запуск заданий берёт список из БД (`jobs`), а не из дерева (`widgets/AgentPlanner.py:138-149`), поэтому фильтрация отображения архитектурно не влияет на планирование — это свойство нужно **зафиксировать тестом**, чтобы его не сломали будущие правки.
* Изоляция проектов обеспечивается выборкой `TeamCache.jobs(project)` (`services/team_cache.py:281-283`), а не UI-фильтром.

## 2. Целевое поведение (предлагаемые имена фиксируются тестами)

* `AgentPlanner.search_edit: QLineEdit` — поле поиска в тулбаре, `objectName="agentPlannerSearch"`, placeholder «Поиск по названию и тексту…», очистка штатной кнопкой `setClearButtonEnabled(True)`.
* `AgentPlanner.query() -> str` — текущий нормализованный запрос (`self.search_edit.text().strip().casefold()`).
* `AgentPlanner._matches(job, query) -> bool` — совпадение по `job["title"]` **или** `job["prompt"]`, регистронезависимо, подстрокой, без учёта `%`, `_`, скобок и regex-синтаксиса (буквальное сравнение в Python, не SQL `LIKE` и не `regex`).
* `AgentPlanner._visible_jobs(jobs) -> list` — список для отрисовки; вход всегда уже отфильтрован по проекту.
* Тексты оверлея: `NO_JOBS = "Нет запланированных задач"` (проект пуст) и `NO_MATCHES = "Ничего не найдено"` (запрос не дал совпадений).
* Подпись перерисовки расширяется запросом: `(root, query, jobs)` — иначе AC-2 недостижим при неизменном наборе заданий.

| Требование | Критерии |

## 4. Критерии приёмки (проверяемые утверждения)

### AC-1. Поиск по названию и по тексту, без учёта регистра
1. Запрос `провер` находит задание с названием «Проверить сборку» (совпадение в середине слова, не только с начала).
2. Тот же запрос находит задание, у которого совпадение есть **только** в `prompt` («Проверить граф»), при названии без совпадений.
3. Регистр не важен в обе стороны: `ПРОВЕР`, `провер`, `ПрОвЕр` дают одинаковый набор `id` заданий; то же для латиницы (`BUILD`/`build`).
4. Кириллица с `ё` не теряется: запрос `ёж` находит «Ёжик», запрос `ЕЖ` находит «ежик» (нормализация `casefold`, без замены `ё → е` в логике фильтра).
5. Совпадение по названию **или** по тексту — логика «ИЛИ»: задание с совпадением в обоих полях показывается один раз (дубликатов пунктов нет).

### AC-2. Реактивность: список обновляется по мере ввода
6. После изменения текста в поле поиска дерево перерисовывается **в том же цикле обработки событий**: достаточно `search_edit.setText(...)` + обработка событий Qt; не требуется `Enter`, кнопка «Найти» или ожидание тика таймера (5 с, `widgets/AgentPlanner.py:80-82`).
7. Обновление работает и при неизменном наборе заданий в БД: запрос входит в подпись перерисовки (`widgets/AgentPlanner.py:120`), поэтому смена запроса — всегда перерисовка.
8. Каждое нажатие клавиши даёт не более одной перерисовки дерева; новые SQL-запросы на каждый символ не обязательны (допустимо переиспользовать список, полученный в `refresh`).
9. Таймер панели не сбрасывает введённый запрос: после тика `refresh()` (и после изменения набора заданий извне) фильтр остаётся применённым, текст в поле сохраняется.

### AC-3. Очистка поля возвращает все задания проекта
10. Пустая строка и строка из одних пробелов трактуются как «фильтра нет»: набор `id` в дереве совпадает с набором `id` из `TeamCache.jobs(project)`.
11. Штатная кнопка очистки поля (clear button) делает то же самое без дополнительных действий.
12. После очистки оверлей (и «Нет запланированных задач», и «Ничего не найдено») скрыт, если задания есть.

### AC-4. Пустые состояния различимы
13. Если в проекте есть задания, но ни одно не совпало, в области дерева виден текст «Ничего не найдено» (точное совпадение строки), оверлей «Нет запланированных задач» не показан.
14. Если в проекте вообще нет заданий, показан «Нет запланированных задач», а не «Ничего не найдено», — даже при непустом запросе.
15. При отсутствии совпадений в дереве нет ни одного видимого элемента, включая заголовки групп ролей (пустые группы не создаются): `tree.topLevelItemCount() == 0`.
16. Оверлей не перехватывает мышь (`WA_TransparentForMouseEvents`, `widgets/AgentPlanner.py:73`) и корректно позиционируется при изменении размера (`widgets/AgentPlanner.py:151-154`).

### AC-5. Поиск влияет только на отображение, не на планирование
17. Задание, скрытое фильтром, всё равно запускается по расписанию: при `state="queued"`, `due <= now`, выполненном `required_file` и простое команды `refresh()` переводит его `queued → running` и вызывает `team.submit(...)` ровно один раз (`widgets/AgentPlanner.py:138-149`).
18. Поиск не меняет БД: до и после ввода запроса совпадают `COUNT(*)`, `id`, `state`, `reason`, `owner`, `due`, `required_file` всех заданий проекта. Никаких `DELETE`/`UPDATE` из UI-фильтра.
19. Отмена/несовпадение фильтра не влияет на `claim` и на защиту от параллельного запуска (`services/team_cache.py:162`): фильтр не приводит к повторному запуску одного задания.
20. Фильтр не влияет на признак «нет активного задания»: если задание скрыто фильтром и уже `running`, панель не пытается запустить его снова.

### AC-6. Сохранены открытие, удаление и сворачивание
21. Двойной щелчок по **найденному** заданию открывает диалог редактирования с заполненными полями (тот же путь, `widgets/AgentPlanner.py:77-78`); двойной щелчок по заголовку группы роли по-прежнему ничего не открывает.
22. Удаление найденного задания работает: подтверждение, кнопка `agentPlannerDelete`, строка исчезает из БД и из дерева, список под активным фильтром перерисовывается; при фильтре, который больше ни с чем не совпадает, показывается «Ничего не найдено».
23. Отмена удаления оставляет задание и в БД, и в дереве (фильтр не «теряет» пункт).
24. Сворачивание работает: `_toggle_collapsed()` скрывает дерево и поле поиска, повторный клик возвращает оба; таймер `planner.timer.isActive()` остаётся `True` (`tests/test_agent_planner_delete.py:8-14` проходит без изменений).
25. Настройка блокировок из `edit()` не регрессирует: кнопка «Удалить задание» по-прежнему недоступна для `running` с живым владельцем (сохраняется поведение `widgets/AgentPlanner.py:218-229`).

### AC-7. Нет утечки заданий других проектов
26. Задание другого проекта с названием, точно совпадающим с запросом, не появляется в дереве ни при каком запросе: поиск применяется только к результату `TeamCache.jobs(project)` (`widgets/AgentPlanner.py:119`, `services/team_cache.py:281-283`), а не к общей таблице `jobs`.
27. Никакой запрос не даёт видимых элементов, если у текущего проекта заданий нет, при наличии заданий в других проектах (набор `id` в дереве пуст).
28. Удаление чужого задания остаётся невозможным: попытка удалить задание другого проекта даёт предупреждение «…уже удалено или недоступно», строка другого проекта остаётся в БД (`tests/test_agent_planner_delete.py:132-144` проходит без изменений).
29. Смена открытого проекта (другой `_project_root()`) сбрасывает/переприменяет фильтр к заданиям нового проекта: в дереве нет заданий предыдущего проекта, даже если запрос не менялся.

### AC-8. Устойчивость ввода
30. Спецсимволы трактуются буквально и не ломают панель: запросы `%`, `_`, `(`, `[`, `*`, `\`, `'` не вызывают исключений и не дают «совпадений со всем». Запрос `100%` находит только задания, содержащие `100%`.
31. Очень длинный запрос (например, 500 символов), эмодзи и сочетания из разных алфавитов не вызывают исключений; отсутствие совпадений даёт «Ничего не найдено».
32. Задания с пустым `prompt` или `title` (данные из старых БД) не ломают фильтр: сравнение выполняется по нормализованным строкам, `None` трактуется как пустая строка.

### AC-9. Вид и данные пунктов не изменились
33. Для видимых пунктов сохранены: текст `title · статус`, группировка по роли с раскрытыми группами, `ToolTip` с `prompt` и причиной, данные задания в `QtCore.Qt.ItemDataRole.UserRole` (`widgets/AgentPlanner.py:127-135`).
34. Поиск не меняет подписи состояний (`Ожидает/Назначено/Завершено/Приостановлено`, `Приостановлено · прервано`) и не влияет на восстановление прерванных заданий (`widgets/AgentPlanner.py:105-114`).
35. Поле поиска оформлено через `objectName` и тему (`design/theme.qss:1227-1246`), не ломает существующие селекторы `agentPlannerTree/agentPlannerButton/agentPlannerAdd`.

### AC-10. Производительность и регрессии
36. При 200 заданиях в проекте ввод символа и перерисовка занимают < 100 мс на типовой машине; набор тестов проекта (`pytest -q`) остаётся зелёным.
37. Существующие тесты панели и хранилища не изменяются по смыслу: `tests/test_agent_planner_delete.py`, `tests/test_team_cache.py:145-171`, `tests/test_agent_team.py:73`, `tests/test_job_recovery.py`.

## 5. Сценарии для тестировщика (ручные, UI)

Подготовка: открыть проект, в панели команды раскрыть «Отложенные агенты», создать задания (кнопка «+»):
`A` — название «Проверить сборку», запрос «Собери проект и проверь ошибки»;
`B` — название «Обновить документацию», запрос «Проверь README на устаревшие команды»;
`C` — название «Молчаливое задание», запрос «Без ключевых слов»;
срок у всех — в будущем (например, +1 час), чтобы ничего не запускалось.

| № | Шаги | Ожидаемо |
|---|---|---|
| S1 | Ввести в поиск `провер` | Видны A и B (в B совпадение только в тексте), C скрыт; «Ничего не найдено» не показано |
| S2 | Ввести `ПРОВЕР` | Тот же результат, что S1 (без учёта регистра) |
| S3 | Ввести `сборку` | Видна только A (совпадение в названии) |
| S4 | Ввести `readme` | Видна только B (регистронезависимо, латиница в тексте) |
| S5 | Ввести `zzz` | Дерево пусто, в области дерева «Ничего не найдено»; «Нет запланированных задач» не видно |
| S6 | Очистить поле кнопкой × | Видны A, B, C, оверлея нет |
| S7 | Ввести `   ` (пробелы) | Видны A, B, C |
| S8 | Свернуть планировщик при активном фильтре, подождать 10 с, развернуть | Дерево и поле поиска скрыты/возвращены, текст запроса сохранён, фильтр всё ещё применён |
| S9 | При фильтре `провер` дважды щёлкнуть по A | Открылся диалог задания с полями A; закрыть «Отмена» — пункт на месте |
| S10 | При фильтре `провер` открыть A, нажать «Удалить задание», подтвердить | A исчез из дерева и из «Журналов»-списка заданий; видна только B; в БД строки A нет |
| S11 | При фильтре `провер` открыть A, «Удалить задание», нажать «Отмена» | A остаётся в дереве под фильтром |
| S12 | Ввести `zzz`, затем вернуть срок задания C на «сейчас + 1 мин», дождаться | C запускается по расписанию (появляется в работе/журнале), несмотря на скрывающий фильтр `zzz` |
| S13 | Открыть второй проект, где есть задание со словом `провер`; вернуться в первый | В первом проекте видны только его задания; задание второго проекта не появляется ни при каком запросе |
| S14 | Ввести `100%`, `(`, `*`, очень длинную строку и эмодзи | Панель не падает, поведение — «нет совпадений» либо точное буквальное совпадение |
| S15 | Создать задание с названием «Ничего не найдено» и ввести `ничего` | Показан пункт-задание; оверлей не путается с названием (текст оверлея не является пунктом дерева) |
