# CodeLane IDE

**CodeLane** — современная, легковесная и производительная среда разработки (IDE) для рабочего стола Windows, разработанная на Python и PyQt6. Интерфейс выполнен в виде эргономичного тёмного воркбенча (VS Code-style), ориентированного на комфортную работу с кодом, проектами и терминалом.

---

## Основные возможности

### 1. Многоязычный редактор кода
- **Подсветка синтаксиса** для более чем 20 языков программирования и разметки: Python, JavaScript, TypeScript, C, C++, C#, Go, Rust, Java, PHP, Ruby, Lua, HTML, CSS, JSON, Markdown, Shell/Bash, YAML, Dockerfile и др.
- **Разделение рабочей области (Split Editor)**: просмотр и редактирование нескольких файлов одновременно (`Ctrl+\`).
- **Быстрый переход и поиск**:
  - Быстрое открытие файлов: `Ctrl+P`.
  - Палитра команд: `Ctrl+Shift+P`.
  - Поиск и замена по файлу: `Ctrl+F` / `Ctrl+H`.
  - Глобальный поиск по проекту во вкладке Search.
- **Интеллектуальное автосохранение** и восстановление рабочих сессий между перезапусками.

### 2. Запуск кода и автоматический поиск компиляторов
- **Автопоиск компиляторов и интерпретаторов**: CodeLane умеет автоматически сканировать систему (переменные PATH, стандартные директории установки SDK и пакетов) и обнаруживать установленные среды разработки:
  - **Python**: системный интерпретатор, виртуальные окружения, Python Launcher.
  - **JavaScript / TypeScript**: Node.js, `tsc`, `ts-node`.
  - **C / C++**: GCC (MinGW/MSYS2), Clang, MSVC (`cl.exe`).
  - **C#**: .NET CLI (`dotnet`), Roslyn/Framework (`csc.exe`).
  - **Go**: `go`.
  - **Rust**: `rustc`, `cargo`.
  - **Java**: `javac`, `java` (Oracle JDK, OpenJDK).
  - **PHP, Ruby, Lua**: соответствующие интерпретаторы.
  - **Shell**: Bash, Git Bash, WSL.
- **Запуск в один клик (`F5`)**: исполнение текущего файла или проекта напрямую во встроенном терминале без необходимости ручной настройки.
- **Управление компиляторами**: отдельная вкладка в настройках позволяет как задать кастомные пути к исполняемым файлам, так и выполнить автоматическое сканирование одной кнопкой.

### 3. Интегрированный терминал
- Встроенная консоль Windows / Shell (`Ctrl+``) с поддержкой нескольких вкладок.
- Удобное управление сессиями: создание вкладок, переключение, остановка процессов (`Ctrl+C`), очистка буфера.
- Связь с редактором: команды сборки и запуска передаются непосредственно в активную терминальную вкладку.

### 4. Управление проектами и файловый менеджер
- **Менеджер проектов**: диалог управления локальными проектами с карточками, историей последних открытых директорий, настройкой команд запуска и безопасным удалением проектов из списка.
- **Древовидный проводник (Explorer)**: полноценная навигация по файловой системе проекта, создание новых файлов и папок, переименование и удаление.
- **Шаблоны новых файлов**: при создании файла предлагаются заготовки (Python-модуль, Qt-виджет, тест pytest, README) с подстановкой имени, даты и автора; шаблоны лежат в `.codelane/templates/` и правятся как обычные JSON-файлы.
- **Интеграция с Git**: боковая панель контроля версий с отображением текущей ветки, изменённых файлов, индексацией (`Stage All`) и созданием коммитов.

### 5. Встроенные просмотрщики документов
- **Markdown Viewer**: просмотр разметки документации в реальном времени.
- **PDF Viewer**: встроенный просмотр PDF-файлов и спецификаций без необходимости сторонних программ.
- **Hex Viewer**: безопасный шестнадцатеричный просмотр бинарных файлов и исполняемых модулей с защитой редактора от повреждения кодировок.

### 6. Персонализация и темы
- Палитра готовых тем оформления: **Dark**, **Midnight**, **Graphite**, **Nord**, **Light**.
- Гибкая настройка интерфейса: размеры шрифтов редактора и интерфейса, высота панелей, параметры автосохранения.

## Быстрый запуск из исходного кода

### Требования
- Python 3.15.2 (64-bit). Для 32-битной Windows-сборки отсутствуют готовые пакеты некоторых зависимостей, включая PyMuPDF и PyQt6.
- Операционная система Windows (также поддерживается базовый запуск на Linux).

### Установка и запуск

1. Клонируйте репозиторий:
```bash
git clone https://github.com/stand4r/PyScribe.git CodeLane
cd CodeLane
```

2. Установите 64-битный Python 3.15.2, создайте виртуальное окружение и установите зависимости.
```powershell
py -3.15-64 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -c "import struct; print(struct.calcsize('P') * 8)"  # должно вывести 64
python -m pip install -r requirements.txt
```

3. Запустите приложение:
```bash
python main.py
```
*(Или воспользуйтесь `CodeLane.vbs` для тихого запуска без консольного окна Windows).*

При открытии проекта CodeLane создаёт в его корне папку `.codelane`.
В ней хранятся параметры проекта, вкладки и позиции курсоров, история терминала, задачи и чат.

## Сборка автономного `.exe` и установщика

CodeLane поддерживает создание полностью автономного исполняемого файла, не требующего наличия установленного Python на целевом компьютере.

### 1. Сборка портативного `.exe`
Запустите скрипт:
```cmd
build_exe.bat
```
Скрипт выполнит сборку через `PyInstaller` по спецификации `CodeLane.spec`. Готовый бандл появится в папке `dist\CodeLane\`, а главный исполняемый файл — `dist\CodeLane\CodeLane.exe`.

### 2. Сборка инсталлятора (Inno Setup)
После успешной сборки `.exe` запустите:
```cmd
installer\build_installer.bat
```
*(Требуется установленный Inno Setup 6).*  
Установщик `CodeLane-Setup-v<версия>.exe` появится в папке `installer_output\`. Номер версии берётся из файла `VERSION`.

## GitHub-токен: разработка и публикация

Встроенная интеграция с GitHub и ручной `git push` используют один и тот же Personal Access Token
(scope `repo`).

- **Где хранится:** `config/github_auth.json` (создаётся при входе через панель Git) или переменная
  окружения `GITHUB_TOKEN` / `GH_TOKEN` — переменная приоритетнее.
- **Файл игнорируется git:** `config/github_auth.json` указан в `.gitignore` (строка 36), в репозитории
  лежит только `config/github_auth.json.example`. Никогда не коммитьте реальный файл и не снимайте
  его с ignore.
- **Не выводите токен в терминал:** ни `echo $GITHUB_TOKEN`, ни `git remote add origin https://<token>@github.com/...`.
  Токен в URL remote сохраняется в `.git/config` открытым текстом. CodeLane передаёт секрет git через
  окружение (`GIT_CONFIG_*` → `http.extraheader`) и маскирует его в выводе, remote остаётся чистым.
- **Ручной push из терминала:** `python tools/push_github.py [--branch <ветка>]` — читает токен из
  файла/ENV, не печатает его, маскирует вывод git и не пишет секрет в конфиг.
- **Проверка гигиены:** `git check-ignore -v config/github_auth.json` и
  `git log --all -- config/github_auth.json` (в истории файла быть не должно).
- **При подозрении на утечку:** немедленно отозвать токен на github.com/settings/tokens, выпустить
  новый, при необходимости вычистить `.git/config` (`git remote set-url origin https://github.com/<owner>/<repo>.git`).
